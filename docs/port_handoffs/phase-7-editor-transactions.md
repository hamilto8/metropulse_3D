Objective and explicit non-goals: Restore the complete editor command surface, live terrain preview, structured placement decisions, zoning, and atomic world edits. This slice deliberately keeps the `road-graph` participant as stable metadata; custom routing, bridge deck/hazard ownership, and traffic feedback belong to work items 7.6 and 7.7. It also does not yet claim durable save/reload or the Phase 7 exit gate.

Command API and ownership: Session-owned `CityEditorRuntime` exposes active/tool state, catalog filtering and tier unlocks, aim, controller navigation, grid toggle, blueprint rotation, place, zone, select, move, selected rotation, demolish, and cancel. `SessionShell` creates it only after the world, player-control, economy, and scheduler owners exist and shuts it down before the economy. The `EditorPresentation` subtree contains only the reticle and transparent green/red ghost; `WorldEditCoordinator`, `EconomyLedger`, occupancy, and zone dictionaries remain the state authorities.

Placement decision contract: `PlacementWorldRules` is the canonical world-query adapter into `PlacementIntelligence`. It terrain-conforms aim, samples water and slope against the physical footprint, checks world bounds, protected Central Park/bridge/space landmarks, player occupancy, authored and player colliders, authored and connected roads, development-zone compatibility, catalog and East-district access, service capacity, fiscal policy, and funds. `PlacementDecision.Blockers` remains priority-sorted; `PrimaryBlocker` supplies the one message/remedy presentation should display. The same decision instance is required by a command, so the preview and mutation policy do not diverge.

Transaction participant list and order: Every building lifecycle command uses exactly `visual-node`, `collider`, `road-graph`, `economy-record`, `occupancy`, `zoning-metadata`, `service-metadata`, and `persistence-record`. The coordinator rejects any missing, extra, or reordered participant. A compensation is registered before apply, possibly-partial throws compensate, false no-mutation rejection does not invoke its inverse, and rollback runs strict reverse order. Place includes treasury debit; demolish includes canonical 50% salvage; move and rotate replace the exact record across all eight participants.

Godot integration boundaries: Visuals and `StaticBody3D` colliders are live `UserWorld` nodes. User colliders register with `WorldCollisionRegistry` and are removed on move/demolish/rollback. The economy participant registers catalog-derived `EconomyBuilding` records. Occupancy projects precise placed footprints for subsequent validation. Road, zoning, service, and persistence participants retain stable records for the next integration slices. Zone creation accepts only Residential, Commercial, and Operations, charges the canonical 2,500 zoning cost transactionally, adds a terrain overlay, publishes an `EconomyZoneEffect`, and retains a persistence-facing parcel record.

Failure and lifecycle evidence: Pure tests inject a failure independently at all eight placement participants and assert full treasury/store restoration. A late persistence failure during move restores the exact prior record in every participant and the economy. Live headless coverage runs zone, valid preview, place, controller navigation, move, rotate, cancel/select, demolish, invalid-water preview, and deactivation; cardinalities return to the authored 258 colliders and 23 economy records after demolition.
